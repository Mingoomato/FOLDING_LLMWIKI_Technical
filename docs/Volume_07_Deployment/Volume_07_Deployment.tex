\section{Container Images}
\label{sec:deploy:containers}

\texttt{Dockerfile} multi-stage build:

\begin{verbatim}
# Build stage
FROM rust:1.78 AS builder
WORKDIR /app
COPY . .
RUN cargo build --release --features api,embed-onnx

# Runtime stage
FROM debian:bookworm-slim
RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates libssl3 libgomp1 && \
    rm -rf /var/lib/apt/lists/*
COPY --from=builder /app/target/release/llmwiki /usr/local/bin/
COPY --from=builder /app/config/default.toml /etc/llmwiki/
EXPOSE 8080
USER 1000:1000
ENTRYPOINT ["llmwiki", "server"]
\end{verbatim}

Images published to \texttt{ghcr.io/llmwiki/llmwiki}:{version, latest, sha}.

\subsection{Image Variants}
\label{sec:deploy:variants}

\begin{itemize}
  \item \texttt{llmwiki:cpu} - Default, ONNX Runtime CPU
  \item \texttt{llmwiki:cuda} - CUDA 12.x, TensorRT optimized
  \item \texttt{llmwiki:rocm} - AMD ROCm support
  \item \texttt{llmwiki:minimal} - No embedder, external embedding service
  \item \texttt{llmwiki:full} - All parsers, local LLM (llama.cpp)
\end{itemize}

\subsection{Stateful Considerations}
\label{sec:deploy:stateful}

LLMWiki pods are \textbf{stateful} due to \texttt{.llmwiki/} directory. Options:

\begin{enumerate}
  \item \textbf{Shared PVC (ReadWriteMany)}: NFS, CephFS, Longhorn RWX. Single writer enforced by file lock.
  \item \textbf{Per-pod PVC + Sync Sidecar}: Each pod has PVC; sidecar runs \texttt{rsync} or \texttt{git sync} for convergence. More complex but no RWX dependency.
  \item \textbf{Object store backend}: S3/GCS for units/graph/index. Requires GraphStore/Index implementations with S3 backend.
\end{enumerate}

\textbf{Default:} Per-pod PVC + \texttt{lsyncd} sidecar for near-real-time sync.

\section{Local-First Deployment}
\label{sec:deploy:local}

\subsection{Single Binary}
\label{sec:deploy:single-binary}

\begin{verbatim}
# Install
curl -L https://github.com/llmwiki/llmwiki/releases/latest/download/llmwiki-x86_64-unknown-linux-gnu.tar.gz | tar xz
sudo mv llmwiki /usr/local/bin/

# Initialize repository
llmwiki init --repo ~/.llmwiki

# Ingest
llmwiki ingest ~/projects/my-codebase

# Run server
llmwiki server --bind 127.0.0.1:8080
\end{verbatim}

\subsection{Air-Gapped Installation}
\label{sec:deploy:airgap}

\begin{enumerate}
  \item Download \texttt{llmwiki-airgap.tar.gz} (contains binary, models, grammars, config)
  \item Extract on target machine
  \item Run \texttt{./install.sh} (sets up systemd service, configures firewall)
  \item No external network access ever required
\end{enumerate}

Air-gap bundle includes:
\begin{itemize}
  \item Embedding models (ONNX): \texttt{bge-m3}, \texttt{e5-large-v2}
  \item Cross-encoder: \texttt{ms-marco-MiniLM-L-6-v2}
  \item Tree-sitter grammars: all 20+ languages
  \item Optional local LLM: \texttt{llama-3.1-8b-instruct-q4\_k\_m.gguf}
\end{itemize}

\section{Backup and Recovery}
\label{sec:deploy:backup}

\subsection{Backup Strategy}
\label{sec:deploy:backup-strategy}

\begin{enumerate}
  \item \textbf{WAL replay}: \texttt{.llmwiki/wal/} is append-only; replay from any point
  \item \textbf{Snapshots}: Periodic \texttt{tar} of \texttt{.llmwiki/} (exclude \texttt{wal/*.jsonl} if replay from snapshot)
  \item \textbf{Incremental}: \texttt{rsync --link-dest} for efficient daily backups
  \item \textbf{Verification}: Restore to temp dir, run \texttt{llmwiki verify} (checksums, query smoke test)
\end{enumerate}

\subsection{Automated Backup (CronJob)}
\label{sec:deploy:backup-cron}

\begin{verbatim}
# Kubernetes CronJob
apiVersion: batch/v1
kind: CronJob
metadata:
  name: llmwiki-backup
spec:
  schedule: "0 2 * * *"  # Daily 2 AM
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: backup
            image: ghcr.io/llmwiki/backup:sid
            env:
            - name: SOURCE_DIR
              value: "/data/.llmwiki"
            - name: DEST_BUCKET
              value: "s3://llmwiki-backups/prod"
            - name: ENCRYPTION_KEY
              valueFrom:
                secretKeyRef:
                  name: llmwiki-backup-key
                  key: key
            command: ["/backup.sh"]
          restartPolicy: OnFailure
\end{verbatim}

\subsection{Disaster Recovery}
\label{sec:deploy:dr}

\begin{enumerate}
  \item Provision new PVC / disk
  \item \texttt{rsync} latest backup to \texttt{.llmwiki/}
  \item Start single pod with \texttt{--replay-wal} flag
  \item Verify \texttt{llmwiki verify --deep}
  \item Scale to target replicas
\end{enumerate}

RTO: ~5 min (depends on data size). RPO: 24h (daily backup) or continuous (WAL shipping to S3).

\section{Upgrades and Migrations}
\label{sec:deploy:upgrades}

\subsection{Version Compatibility}
\label{sec:deploy:compat}

\begin{itemize}
  \item \textbf{Patch (0.1.x)}: Rolling upgrade, zero downtime
  \item \textbf{Minor (0.x.0)}: May require index rebuild; blue-green deploy recommended
  \item \textbf{Major (x.0.0)}: Schema migration; downtime required; migration tool provided
\end{itemize}

\subsection{Index Migration}
\label{sec:deploy:index-migration}

When HNSW parameters change (M, ef\_construction) or embedder model changes:

\begin{verbatim}
# Rebuild index from units
llmwiki index rebuild --repo .llmwiki --model bge-m3 --parallel 4

# Or incremental: re-embed changed units only
llmwiki index reembed --repo .llmwiki --since 2024-01-01
\end{verbatim}

Migration runs as Kubernetes Job or standalone binary.

\subsection{Graph Migration}
\label{sec:deploy:graph-migration}

Schema changes (new node types, edge types, property changes):

\begin{verbatim}
llmwiki graph migrate --repo .llmwiki --to-version 2
# Dry-run first:
llmwiki graph migrate --repo .llmwiki --to-version 2 --dry-run
\end{verbatim}

\section{Security Hardening}
\label{sec:deploy:security}

\begin{itemize}
  \item \textbf{Non-root}: Container runs as UID 1000
  \item \textbf{Read-only rootfs}: \texttt{readOnlyRootFilesystem: true}
  \item \textbf{No capabilities}: \texttt{drop: [ALL]}
  \item \textbf{Network policies}: Ingress only from API gateway; egress only to model registry (if remote)
  \item \textbf{Secrets}: API keys, OIDC secrets via Kubernetes Secrets / Vault
  \item \textbf{Auth}: OIDC, API keys, mTLS for service-to-service
  \item \textbf{Rate limiting}: Per-user, per-IP, per-API-key
  \item \textbf{Audit logging}: All queries logged with user, query hash, result count
\end{itemize}

\textbf{Claim 10:} A deployment architecture for a semantic operating layer wherein: (a) the entire system state is contained in a single filesystem directory enabling backup via standard file copy, (b) the system runs as a single stateless binary with embedded models requiring zero external services, (c) air-gapped operation is supported via a self-contained bundle including all models and grammars, and (d) deterministic replay is achieved by directory synchronization without auxiliary coordination services.

\section{Summary}
\label{sec:deploy:summary}

LLMWiki deployment prioritizes:
\begin{enumerate}
  \item \textbf{Operational simplicity}: Single binary, filesystem state, no external deps
  \item \textbf{Local-first}: Works fully offline, air-gapped
  \item \textbf{Production readiness}: K8s native, observability, HA, security
  \item \textbf{Recoverability}: WAL replay, snapshot restore, verified backups
  \item \textbf{Upgradability}: Blue-green, rolling, migration tooling
\end{enumerate}
